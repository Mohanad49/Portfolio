- Follow the owner's approved plan in tasks/plan.md and confirmed product truth
  in PRODUCT.md. Do not reopen settled preferences or expand the feature set.
- No em dashes in authored copy, documentation, code comments, or UI strings.
- Challenge unsupported claims. Never invent metrics, evidence, or testimonials.
- Use this checkout for the replacement. Do not edit the original checkout.

## Skill routing

The ownership table in tasks/plan.md is authoritative. Activate only the owner
for the work at hand. A reference to another skill does not activate its workflow.

- portfolio-case-study-writer: factual narrative structure before visual work.
- Impeccable: visual direction, UX, UI implementation, and visual acceptance.
- imagegen: raster production from Impeccable's asset briefs, no independent design.
- git-workflow-and-versioning: checkout, branch, commits, and PR mechanics only.
- code-review-and-quality: source correctness, architecture, security, dependencies,
  and resource handling; no competing aesthetic review.

Use official framework/library documentation for API details. Do not install the
six skill additions rejected by the approved plan or add a second design pipeline.

## Workflow

- Track progress in tasks/todo.md and decisions in DECISIONS.md.
- Image concepts require the owner's selection before UI implementation.
- Keep small, coherent commits with meaningful messages and relevant verification.
- Reuse verification results for an unchanged source tree. Rerun affected checks
  after corrections, and recapture when the rendered result changes.
- Record results and unresolved findings in docs/verification.md. Do not claim a
  release is ready on a visual verdict or technical verdict alone.
- Impeccable owns its required visual reviewer/documenter handoffs. Do not start
  additional overlapping reviewers or alternate design workflows.
