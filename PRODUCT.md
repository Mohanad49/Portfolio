# Mohanad Yehia: Software QA Portfolio

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated by the owner and approved in the implementation plan: Astro, TypeScript,
Tailwind CSS, React islands, React Three Fiber/Three.js, GSAP, and pnpm. Static
content is delivered as HTML. React is limited to interactive islands. GSAP owns
DOM timelines and scroll progress; React Three Fiber owns the renderer and scene
lifecycle. There is no application backend or public API in v1.

## Users

Recruiters scanning a Software QA Engineer's work and hiring engineers reviewing
the decisions and evidence behind it. Mobile and desktop visitors must both have
a complete experience.

## Product Purpose

Present Mohanad's production QA ownership and public technical work through a
memorable personal website. Make his role, selected work, resume, and contact
methods easy to reach, with deeper case studies for technical reviewers.

## Positioning

Broad Software QA: risk assessment, test design, manual and exploratory testing,
web/mobile/API automation, SQL verification, CI, and evidence-based evaluation.
The portfolio must not reposition him as exclusively an SDET or AI specialist.

## Operating Context

The new project is an isolated checkout of Mohanad49/Portfolio on
dev/qa-portfolio. Its final deployment replaces the current website through the
existing Vercel project at https://myehia.vercel.app. The original local checkout
and previous production deployment are recovery points.

## Capabilities and Constraints

- Homepage, three detailed case studies, filterable framework archive, resume PDF,
  a useful 404 page, and legacy route/bookmark compatibility.
- Featured order: TestPulse, Cal.diy QA Strategy, LLM Evaluation Harness.
- Contact through visible email, copy-email feedback, LinkedIn, and GitHub.
- Preserve the current real portrait and use the supplied updated resume.
- Employer content is limited to resume facts and conceptual artwork. Internal
  screenshots, documents, production data, and private repositories are excluded.
- Keep TestPulse snapshots distinct from live data, Cal.diy v6.2.0 distinct from
  hosted Cal.com, and the LLM refusal judge distinct from CI gates.
- Public evidence links and metrics must retain their scope and limitations.
- Do not add a contact backend, CMS, guestbook, blog, or extra motion library.

## Brand Commitments

Mohanad Yehia, Software QA Engineer. The owner chose a cinematic quality-lab
direction with graphite surfaces, bright typography, controlled amber lighting,
original layered inspection artwork, and varied editorial layouts. Image
concepts must be reviewed before UI implementation. Detailed aesthetic decisions
and the chosen composition belong to the surface brief, not this product record.

## Product Principles

1. The role and evidence stay understandable while the frontend earns attention.
2. Every factual claim has a source; unknown details are omitted.
3. Original conceptual artwork never masquerades as a real report or employer UI.
4. Content, resume, and contact remain usable when enhancements are unavailable.
5. One skill owns each responsibility; the approved execution plan governs scope.

## Accessibility & Inclusion

Target WCAG 2.2 AA with keyboard/focus/contrast/zoom checks and zero serious or
critical axe findings in this portfolio. Reduced-motion, JavaScript-disabled,
and unsupported-WebGL states retain the core content. Mobile has a deliberate
lightweight adaptation. Color alone never communicates test status.
